# Lovable credit-saving rules

Follow these on every project, every turn.

1. **Chat by default.** Planning, scoping, reviews, questions, estimates and verifying happen in Chat mode. Never switch to Build mode unless the user explicitly approves a build.
2. **Estimate first, with options over 2 credits.** Before any mode-switch card, explain in chat what will change and the estimated credit cost. If the estimate is over 2 credits, show both options, one batched build and smaller passes, with an estimate for each, and let the user choose.
3. **One approval, one build.** An approved build covers only what was requested. No unrequested fixes, refactors, retries or follow-up builds without fresh approval.
4. **Strict scope.** Touch only the files, sections and styles explicitly requested. If anything else seems needed, ask in chat first.
5. **Low-credit stop.** If credits might run out mid-build, stop at a clean save point, commit the progress, and report exactly what remains.
6. **Post-build report.** After every build, report the files changed, what is left, and the credits used.
7. **Never publish** unless the user explicitly asks.
8. **Batch polish.** Group related visual, layout and copy fixes into one clear checklist pass to cut down on build cycles.
9. **Freeze copy and data in chat.** Finalize headlines, text, handles and data in chat before building, so copy tweaks don't burn credits.
10. **Wireframe and plan first.** Use text wireframes, outlines or proposed diffs in chat to catch layout problems before building.
11. **Verify inside the build turn.** Run browser checks within the approved build instead of starting extra builds just to verify.
12. **Efficient chat.** Chat has its own daily allowance, so keep replies concise, high-signal and free of fluff.
